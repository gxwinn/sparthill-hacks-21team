✅ What Works Great

3-Layer DuckDB Audit Engine
Deterministic, zero AI math. NCCI edits, MRF rates, charity care all fire correctly in all tested scenarios. Savings math is exact and mutually exclusive between layers.
Two-Stage PII Redaction Flow
Stage 1 runs fully offline OCR on Windows, masks 7 PII categories, returns a redaction_id cache. Stage 2 consumes the cached bytes. Privacy-first design is correctly enforced.
Auto-Detect + Manual Override Logic
Hospital/payer resolution is smart: auto-detect finds Bay Area MRF matches, falls back to Federal CMS benchmark, and preserves user manual overrides without clobbering their state.
Deterministic Offline Fallback
Without a Gemini API key, all four languages still produce correct summaries, dispute letters, and per-CPT explanations via the CPT translation dictionary. Zero crash on missing key.
Path Traversal Protection
/api/sample-bills/../../etc/passwd correctly returns 404. The target.parent != SAMPLE_BILLS_DIR guard works.
Input Validation via Pydantic
household_size=0 returns a clean 422 with the exact field error. No internal crashes on bad inputs.

🐛 Bugs Found

BUG 1 — High Severity Unicode bullet "•" and "§" rendered as garbage in API responses
All string data returned from the API contains corrupted characters: • becomes a??, § becomes A, é becomes A?. Confirmed in detection_banner_message, sample bill label, Spanish plain_language_summary, and the dispute letter. The data is internally correct UTF-8 but the CSV files are being read with the wrong encoding and stored in DuckDB accordingly.

Root cause: read_csv_auto() in db.py doesn't force UTF-8. If any CSV was saved as Windows-1252 (likely the case for special characters), DuckDB guesses wrong.

Fix: Add encoding='utf-8' to every read_csv_auto() call in db.py, and ensure all CSV files are saved as UTF-8.
BUG 2 — High Severity _GEMINI_NETWORK_UNAVAILABLE is a module-level global that persists across requests
In llm_service.py, once any Gemini API call fails (e.g. a timeout on one request), _GEMINI_NETWORK_UNAVAILABLE = True is set for the entire server lifetime. All subsequent requests — even after the network recovers — permanently skip Gemini and fall back to deterministic mode with no way to reset without restarting the server.

Fix: Use a timestamp-based cooldown (e.g. retry after 60 s) rather than a permanent flag. Or better: remove the global entirely and let each request catch its own exception.
BUG 3 — Medium Redaction cache is unbounded in time — stale sessions silently fail after server restart
_REDACTION_CACHE is an in-memory dict limited to 50 entries by count, but has no TTL. After a server restart, any redaction_id still held by a browser tab is silently invalid, giving users the confusing error "Redacted session expired or missing." The cache also grows unbounded between the count check (it could momentarily exceed 50 concurrent entries under load).

Fix: Store a created_at timestamp per entry and evict entries older than, say, 30 minutes, or display a friendlier "session expired, please re-run Step 1" message before the stage 2 fetch.
BUG 4 — Medium uv run backend exits silently with code 0 when port 8000 is already bound
When port 8000 is occupied, uvicorn raises OSError: [WinError 10048] after startup. The process exits 0, but the log is empty and no user-readable error is emitted to stdout before exit when the process is backgrounded. Developers see silent failure.

Fix: Wrap uvicorn.run() in __init__.py's main() in a try/except and print a clear message: "Port 8000 is already in use. Is another instance running?"
BUG 5 — Low Payer value mismatch: "Other US Hospital" + auto-payer resolves to "Anthem Blue Cross" silently
When the user selects "Other US Hospital" from the dropdown and leaves payer on Auto-Detect, the resolved payer becomes Anthem Blue Cross with banner text "Auto-Detected from Bill: Other US Hospital • Anthem Blue Cross. Because this facility/insurer is outside the Bay Area MRF registry…". The banner then contradicts itself — Anthem is a Bay Area MRF payer but the hospital is not, leading to a confusing CMS benchmark being applied under a named payer label.

Fix: When hospital resolves to "Other US Hospital", default payer to "CMS Medicare Benchmark" instead of "Anthem Blue Cross".

🧭 User Flow Improvements

UX 1 No loading indicator during demo button runs
Clicking "ER Trauma ($10,955)" shows only a tiny status banner saying "Running…" but the demo buttons themselves don't disable or show a spinner. Users double-click them, triggering duplicate requests. The three demo pill buttons should disable and show a loading state while the fetch is in progress.
UX 2 Language change while viewing results re-runs full audit — no user indication
Changing the language dropdown silently fires reanalyzeIfReady() with no loading state on the button or results area. Users don't know the audit is being re-run and may switch language again mid-request. Show a subtle loading overlay or disable the dropdown during re-analysis.
UX 3 "Update Audit ↻" button appears only after editing income/household — but not after changing hospital/payer
showUpdateButtonIfAudited() is called from income, household_size, hospital, and payer listeners — good. But the button is hidden in its initial state with class="hidden" and appears only after results are visible. When results are present and a user then uploads a new bill, the button stays visible but clicking it re-runs the old redaction. It should be hidden or relabeled to avoid confusion.
UX 4 No feedback after "Copy Letter" fails (clipboard API unavailable over HTTP)
navigator.clipboard.writeText() requires a secure context (HTTPS or localhost). Over plain HTTP on any device other than localhost, it throws and the button reads "Copy Failed" permanently until the user reloads. Add a visible inline text fallback: select the <pre> content and tell users to press Ctrl+C/Cmd+C.
UX 5 No suggested income/household pre-fill when picking from sample bills gallery
The /api/meta response already includes suggested_income and suggested_household_size per sample bill. But selectSampleBillByFilename() never uses them — it intentionally only resets the file, leaving the user's income/household untouched. This is fine for returning users, but for first-time users with the default values it means the demo income ($48,000, household 3) may not match what the bill implies. A note like "Suggested income for this bill: $72,000" would help set expectations.
UX 6 "Re-run local PII redaction" button label is confusing after Stage 2 is complete
The small ghost link below the Stage 2 audit button reads "Re-run local PII redaction." After a full audit has been run, pressing it restarts Stage 1 and hides the audit results without any warning. Users might accidentally clear their audit while trying to review the redacted image. The button should either: (a) be removed after Stage 2 completes, or (b) warn "This will clear your audit results."
UX 7 Hero "Try Real Cardiology Bill" quick-start fires Stage 1 without user seeing the preview first
quickStartSample(filename) calls selectSampleBillByFilename() then immediately await runStage1Redaction(). This means the user never sees the "Original Unredacted Bill" stage — they jump straight to scanning, skipping the privacy education moment. The sequential two-stage design intent is bypassed. Consider showing the preview for 1 second before auto-running Stage 1, or keep the quick-start as a single-click demo path only (currently the left panel's own Stage 1/2 flow is the canonical path).

🎨 Design Improvements

DESIGN 1 The "Inspector" button label is cryptic on mobile
On screens < 768 px the button reads "Inspector" only (the "For Judges /" part hides via hidden md:inline). Judges reviewing on a phone see "Inspector" with a terminal icon — no context. Rename mobile label to "Tech Proof" or keep the full label but truncate gracefully.
DESIGN 2 Line item "billed → allowed" layout breaks on narrow mobile
The billed/allowed price comparison row uses sm:flex-col with items-end. On 375 px (iPhone SE), the two price values and the "Save $X" pill all stack in a column and overflow to the right edge due to the fixed shrink-0 on the parent. The price column needs a max-w constraint or the row should be full-width on mobile.
DESIGN 3 Document viewport max-height clips tall bills without a scroll cue
The image frame has max-h-[360px] overflow-auto. Tall multi-page bills are clipped with no visual scroll indicator (no shadow fade or "scroll to see more" affordance). Add a bottom gradient fade on the container when the image overflows.
DESIGN 4 Summary bill scenario (Demo 3) final balance shows full billed amount — visually indistinguishable from "no savings"
When a non-itemized bill runs, final_patient_balance == total_billed and total_savings == 0. The hero summary card shows "Final Fair Balance: $8,450" in large font with "$0.00 Total Waived (0% off)" — this looks like a failed audit, not a deliberate "pending itemization" state. The hero card should display a different layout for the UB-04 request path: replace the savings pill with a "⚠ Audit Paused — Itemization Required" pill.

🔧 Code Quality Notes

CODE 1 _resolve_hospital_and_payer() is ~160 lines of deeply nested conditionals
The logic is correct but very hard to follow. The "if auto + matched", "if auto + external", "if manual + local MRF", "if manual + other" branches with cross-checks between hospital and payer states would benefit from a small state machine or a decision table (4×4 grid). No functional change needed, but a refactor would improve maintainability significantly.
CODE 2 init_db() re-creates all tables on every server start
CREATE OR REPLACE TABLE runs every single time the app boots. This is fine for development but adds ~200 ms startup time with five CSV files. Adding a version/hash check so tables are only rebuilt when the CSVs change would speed up restarts.
CODE 3 get_connection() returns a new DuckDB connection per call with no pooling
Each audit opens a new duckdb.connect() and runs 4–8 queries. With DuckDB's embedded model this is low overhead, but under concurrent load (multiple users) it creates file-lock contention. A singleton connection or connection pool via a thread-local would be safer.
CODE 4 ensure_sample_bills_seeded() is called on every /api/meta and /api/samples hit
The function scans the sample_bills/ directory on every single metadata request. This is disk I/O on a hot path. The result should be cached at startup (already done once in lifespan) and only refreshed on actual file changes.

🏆 Overall Verdict

The core audit engine is solid and production-worthy. The 3-layer DuckDB deterministic audit, NCCI edits, MRF rate lookups, charity care tiers, and the two-stage local PII redaction flow all work correctly across all test scenarios. The fallback chain (Gemini → local OCR → demo preset) is sensible and the codebase is well-organized.

The single most important fix before a public demo is Bug 1 (UTF-8 encoding) — every string displayed to the user or returned from the API currently contains mojibake for any non-ASCII character, which makes the Spanish translation, the bullet separators in banners, and the § legal citations all appear as garbage. This is a one-line fix per read_csv_auto() call but has high visible impact.

The second most impactful fix is Bug 2 (permanent Gemini flag) — once a network hiccup hits in production, the app permanently downgrades to offline mode for all users without any indication.

All UX issues are minor polish. The design is high quality — the bento card layout, GSAP transitions, and typography pairing are well-executed.
